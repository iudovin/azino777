# Решение

Архитектура построена на базе Docker-контейнеров с автоматической инициализацией метаданных, ELT-пайплайнов и BI-дашборда. Вся установка (включая исходные данные и визуализацию) выполняется одной командой, дополнительно ничего докидывать не нужно

## tl;dr

1.
```
git clone https://github.com/iudovin/azino777.git && cd azino777
```
2. Создать файл окружения с кредами (обязательно — мусор `CLICKHOUSE_*` не хардкодится в исходниках):
```
cp .env.example .env   # при необходимости отредактируйте значения
```
3.
```
docker compose up -d --build
```
4. http://localhost:8080/ -> admin/admin, запускаем DAG 00_... -> снимаем с паузы 01_...
5. http://localhost:8088/ -> admin/admin

## 1. Стек 

* **OLTP-хранилище и слой `dds`:** PostgreSQL (версия 13)
* **Слой витрин `dm`:** ClickHouse (версия 24.3)
* **Стриминговая загрузка CSV:** Apache Kafka (версия 3.8, режим KRaft без Zookeeper)
* **ETL:** Apache Airflow (версия 2.9.2), DBT
* **BI:** Apache Superset

## 2. Установка и запуск

Развертывание проекта выполняется из корневой директории командой:

```bash
# 1) создать .env с кредами ClickHouse (пример в .env.example)
cp .env.example .env
# 2) поднять стек
docker compose up -d --build
```

Креды ClickHouse (`CLICKHOUSE_*`) берутся из `.env` (файл в `.gitignore`). При старте `airflow-init` автоматически создаёт подключение `clickhouse_conn` в Airflow; даги читают его через `BaseHook` — логины/пароли в коде не хардкодятся.

## 4. Порядок запуска DAG-ов в Airflow

После поднятия стека откройте Airflow (`http://localhost:8080`) и активируйте конвейеры **строго в следующем порядке**:

1. **`00_init_dwh`** (разовый запуск руками):
* Применяет базовую структуру DDL: схемы (`raw`, `dds`, `dm`), первичные/внешние ключи, констрейнты и индексы в PostgreSQL
* Создаёт витрину `dm.monthly_summary` в ClickHouse (слой витрин, источник дашборда)
* **Внимание!** Повторный запуск сносит и пересобирает БД с нуля

2. **`01_monthly_increment`** (ежемесячный запуск, работает автоматически):
* Публикует содержимое csv-файлов в топики Kafka (`raw.<table>`), потоковый консьюмер идемпотентно заливает их в `raw` PostgreSQL
* DBT идемпотентно обновляет `dds` и витрину `dm.monthly_summary` в PostgreSQL
* Отдельный шаг синхронизирует витрину `dm.monthly_summary` в таблицу ClickHouse (источник дашборда в Superset)
* Повторные запуски не приводят к дублированию или искажению данных


## 5. Архитектура хранилища и документация таблиц

Хранилище организовано по трехслойной модели:

* **`raw` (Сырой слой):** точные копии CSV-файлов со строковыми типами для бесперебойного потокового импорта.

* **`dds` (Детальный слой):** реляционная нормализованная модель с типизацией, проверками целостности (PK/FK), индексами и конвертацией финансовых показателей в USD.

* **`dm` (Слой витрин):** аналитическое представление для отчетности и дашбордов, агрегированное по странам и месяцам. Витрина `dm.monthly_summary` материализуется в PostgreSQL и параллельно синхронизируется в ClickHouse, который является источником данных для дашборда в Superset.

### Слой DM (Слой витрин)

Витрина `dm.monthly_summary` существует в PostgreSQL (представление) и синхронизируется в таблицу `dm.monthly_summary` в ClickHouse (источник дашборда).

#### `dm.monthly_summary` (Представление в PostgreSQL / таблица в ClickHouse)

| Поле | Тип | Описание |
| --- | --- | --- |
| `report_month` | `DATE` | Отчетный месяц (первое число месяца среза: `YYYY-MM-01`). |
| `country` | `VARCHAR` | Страна игрока (или `'Unknown'`). |
| `sum_deposits_usd` | `DECIMAL` | Суммарный объем депозитов в USD за месяц. |
| `sum_withdrawals_usd` | `DECIMAL` | Суммарный объем выводов средств в USD за месяц. |
| `sum_bets_usd` | `DECIMAL` | Суммарный оборот ставок в USD за месяц. |
